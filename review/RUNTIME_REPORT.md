- 内核 6.6.0-159.4.3.154.oe2403sp4.x86_64，Bash 5.2.15，systemd 255，OpenSSH 9.6p1。

- 未授予免密 sudo。普通操作以非 root 身份执行，系统管理步骤通过作者已授权的 root 连接执行。实际带密码 sudo 交互未复现。
- SELinux 全程为 Enforcing，firewalld 保持运行；没有开放应用公网端口。虚拟机时钟未同步，原始日志时刻与宿主机存在偏差，报告日期以宿主机记录为准。

## 执行记录与早期失败

[execution-results.json](runtime/execution-results.json) 有 83 次虚拟机用例执行记录，77 次达到各自预期退出状态，6 次早期失败随后完成修正或在明确条件下重试。重复执行和预期失败均保留，不把这组数字写成 83 个互不重复的成功测试。

- man 缺手册包，安装后复测通过。
- 网络测试驱动少了普通登录会话的 /usr/sbin；按真实登录 PATH 修正后通过。不是 ip 软件包缺失。
- HTTP 监听断言未考虑 IPv4 映射显示；修正匹配后通过。
- 默认 Central 构建遭 403；独立镜像构建成功，原默认入口仍记为失败条件。
- ssh-copy-id 的自动化引导 IdentityFile 让其重复检测使用了已授权旧密钥，误判新公钥已经存在；确认新公钥未安装后，用 -f 执行一次安装，再以新密钥验证通过。这是测试适配，不要求读者无条件使用 -f。
- 前述公钥未装使首轮 SCP 失败；修正后重传并逐字节比较通过。

Windows 隧道另有 [真实 HTTP 结果](runtime/tunnel-results.json)。首次因服务器禁用转发而失败；允许指定测试用户和目标后成功。端口冲突测试使用 Windows 独占监听套接字，得到退出码 255。最初“第二个 SSH 必然因同端口失败”的断言不适用于允许共享绑定的 Windows 情况，该断言已修正。

执行驱动和冻结的 v0.2.0 命令编号保存在 [runtime](runtime/README.md)。v0.2.1 新增或修正的准备命令来自已实际完成的补包、工具链与转发配置步骤，新版代码块编号由静态检查重新生成。
