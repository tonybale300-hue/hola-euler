# 第 23 章 Linux 服务器部署基础

## 23.1 从“运行了”走到“可以维护”

### 23.1.1 部署要留下哪些东西

终端里 java -jar 成功只是起点。离开电脑以后，程序怎样启动，日志去哪里，谁有权修改程序，版本出错怎样恢复，都需要明确。本章先做设计，下一章逐步落地。

我们把不可随意修改的发布产物放在 /opt/labapp/releases，每个版本一个目录。current 是指向当前版本的软链接。可写数据放在 /var/lib/labapp，日志交给 systemd journal。运行账户 labapp 没有交互登录需求，只获取读程序和写自己数据的必要权限。

### 23.1.2 代码与数据需要不同所有者

发布目录由 root 管理，运行账户只读。即使应用发生错误，也不应轻易改写下一次启动的程序文件。数据目录交给 labapp 写入。示例不需要让应用写 /opt，也不需要把系统目录改为 777。

## 23.2 启动前确认四项条件

### 23.2.1 程序、路径、身份和端口

核对上传文件摘要，确认它就是刚构建的产物。用 command -v java 与 java -version 检查运行环境。用 id labapp 和目录权限检查服务身份。用 ss -ltn 检查端口是否已经被占用。任何一项不明确，都应先解决再创建自动重启策略。

路径使用绝对路径。systemd 的工作目录、Java 路径和 JAR 路径应可读可执行；在自己家目录可用的相对路径，换成专用账户不一定仍可用。

### 23.2.2 防火墙与安全策略各做什么

防火墙决定哪些网络流量被允许，SELinux 等安全机制还会限制进程可访问哪些对象。二者与传统 rwx 权限共同影响程序行为。只在已安装对应工具时，可用以下只读查询观察状态。

```bash
systemctl status firewalld.service --no-pager
sudo firewall-cmd --get-active-zones
getenforce
ls -Zd /opt /var/lib
```

firewall-cmd 是 firewalld 的命令行工具，zone 是应用一组网络规则的区域。getenforce 报告 SELinux 模式，ls -Z 显示安全上下文。某项工具不存在不等于所有保护都关闭，应继续确认本机实际机制。不要用关闭防火墙或把 SELinux 改成宽松模式来“修好教程”。

## 23.3 先限制在本机，再决定公开入口

### 23.3.1 SSH 隧道足够完成本书实验

Java 应用监听 127.0.0.1:8080，宿主机通过 SSH 隧道访问。这样本书不必在来宾防火墙中开放 8080，也不要求购买云服务器。SSH 入口仍需按照第 13 章检查服务、网络和认证。

若未来要向真实用户提供服务，应另行设计域名、TLS 证书、反向代理、访问控制与日志保留。反向代理是在前端接收请求、再转交后端应用的服务。不能把本书这个没有鉴权的教学接口直接当作完整生产系统。

### 23.3.2 端口开放也需要证明应用正确

从服务器本机请求 /health，再从隧道请求。前者成功而后者失败，重点检查 SSH 转发和客户端访问地址；两者都失败，回到进程、日志和监听。使用分层证据，比连续修改几个配置后碰运气更容易找到原因。

## 23.4 日志、重启和升级

### 23.4.1 让日志能解释一次失败

日志至少要让人知道发生时间、组件、事件和错误细节，不应写密码或令牌。journalctl 的 -u 按服务筛选，-b 限定本次启动，--since 可以选择起始时间。服务进入 restart 循环时，查看第一条失败信息往往比只看最后一句启动失败更有效。

### 23.4.2 回滚恢复的是哪个部分

保留 v1、部署 v2，再切换 current，必要时切回 v1，可以回退程序文件版本。但数据库结构或可写数据如果已被新版本修改，程序回滚不自动恢复数据兼容性。本书示例不修改持久化业务数据，因而能把重点放在服务与文件版本上。

> 实机核验｜【待 openEuler 24.03 LTS SP4 实机验证】默认防火墙、SELinux 状态、日志权限和服务限制需按安装结果核对。任何拒绝都要记录原因，不把关闭保护作为验收通过。

## 23.5 本章练习

- 不要往前翻｜为什么程序目录由 root 管，而数据目录由 labapp 写？
- 命令填空｜查看某服务本次开机日志可组合 journalctl -u 服务名 ______。
- 看需求写命令｜检查 8080 是否监听，并请求本机健康接口。
- 看命令猜结果｜切回旧 JAR 是否必然撤销数据库中的新字段？
- 找错误｜运行失败就 chmod -R 777 /opt/labapp，会掩盖什么问题？
- 无提示实操｜为自己的实验服务写一页部署说明，包含目录、身份、端口、日志和回滚顺序。
