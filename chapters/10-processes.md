# 第 10 章 进程与任务

## 10.1 文件中的程序怎样变成正在做事的进程

### 10.1.1 观察一个会等待的程序

程序文件保存指令，进程是程序运行时的一个实例。同一程序可以同时启动多次，拥有不同的进程。PID 是 process identifier，进程标识；PPID 是 parent process identifier，父进程标识。

```bash
sleep 120 &
lab_pid=$!
printf '%s\n' "$lab_pid"
ps -p "$lab_pid" -o pid,ppid,stat,comm
```

sleep 的意思是等待，120 表示秒数。& 让命令在后台运行，不占住当前提示符。$! 是 Bash 记录的最近一次后台异步任务的进程号，这里存入变量 lab_pid；等号两边不能有空格。ps 关联 process status，-p 选择 PID，-o 选择输出列。stat 是状态，comm 是命令名称。

### 10.1.2 工作目录、环境与打开的文件

一个进程除了 PID，还带有用户身份、工作目录、环境变量和打开文件等状态。它的子进程通常继承其中一部分。这解释了为什么在某个目录启动程序，会影响它读取相对路径的位置。父进程退出后，子进程的后续处理还取决于会话、信号和服务管理方式，不能只记“父退出，子必死”这样过度简化的规则。

## 10.2 前台、后台与作业

### 10.2.1 当前 Shell 管理的作业

```bash
jobs
```

jobs 就是作业列表，显示当前 Shell 知道的后台或暂停任务。它不能列出整台机器的所有进程。作业编号与 PID 也不相同。fg 关联 foreground，把作业带到前台；bg 关联 background，让暂停作业继续在后台运行。

如果 jobs 显示刚才的 sleep 为当前作业，可以输入 fg 将其恢复到前台，然后用 Ctrl+C 中断。若 120 秒已经过去，作业可能早已结束，先看实际列表，不要机械使用固定编号。Ctrl+Z 通常暂停前台作业，暂停会保留进程并停止其执行，不能代替正常退出。

### 10.2.2 让进程结束

重新创建一条 sleep 任务，立即保存其 PID，再发送信号。

```bash
sleep 120 &
lab_pid=$!
ps -p "$lab_pid" -o pid,comm
kill -TERM "$lab_pid"
```

kill 的名称容易让人以为只有强制杀死一种操作，实际主要用途是发送信号。TERM 请求结束，程序通常有机会清理资源。KILL 则不能被捕获处理，所以不应作为第一选择。这里只对自己刚创建、已核对的 sleep 发信号。PID 会被复用，长时间保存的 PID 不能证明现在仍是原进程。

## 10.3 观察资源使用

### 10.3.1 从动态列表找线索

top 是动态进程监视工具，名称可直接记作上方列出的活跃任务视图，不必编造全称。运行 top 后观察 CPU、内存和进程列表，按 q 退出。一个进程 CPU 较高可以来自正常计算，内存“空闲很少”也可能包含可回收缓存。需要结合请求量、持续时间和系统是否出现延迟判断。

### 10.3.2 进程存在与服务可用

看到 Java 进程仍在，只能证明它尚未退出，不能证明 HTTP 请求能成功。程序可能尚在启动、依赖数据库失败或陷入死循环。后续部署同时检查进程、监听端口、日志和应用响应。
