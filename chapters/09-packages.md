# 第 9 章 DNF 与 RPM

## 9.1 一个命令不存在时该做什么

### 9.1.1 程序、包与仓库

输入 vim 后收到 command not found，先检查拼写和 type vim。确认确实没有后，再找它由哪个软件包提供。软件包把程序、文件清单、版本和依赖关系组织在一起。仓库是发布软件包及索引的位置；索引让管理工具知道有哪些包、适用架构和依赖。

DNF 是高层包管理器，名称沿用 Dandified YUM。RPM 是 RPM Package Manager，负责 RPM 包格式及已安装包数据库等工作。本书使用 DNF 从配置的仓库解析依赖，用 RPM 查询系统中的包与文件归属，不把两者看成互不相干的安装方式。

### 9.1.2 先看系统提供了什么

```bash
dnf --version
dnf repolist
dnf search vim
dnf provides '*/vim'
```

repolist 列出仓库，search 搜索包信息，provides 查询提供某项能力或文件的包。'*/vim' 用单引号保护，避免 Bash 在当前目录先展开星号。查询可能下载元数据，因此需要可用网络；报 DNS、证书或镜像访问错误时，先诊断网络和时间，不要关闭签名检查。

## 9.2 完成一次可审查的安装

### 9.2.1 查看候选包

在本机查询结果中确认编辑器包的准确名称，然后使用 dnf info 查询详情。以下以 vim-enhanced 为候选示例，只有查询确认它来自目标版本的可信仓库后才安装。

```bash
dnf info vim-enhanced
sudo dnf install vim-enhanced
```

安装需要写系统目录和包数据库，所以使用 sudo。DNF 会给出拟安装、升级或移除的包及空间信息。读过交易摘要后再确认。教程不加 -y，让初学者有一次检查依赖变化的机会。若提示找不到该包，回到 provides 的实际结果，不能换一个网上猜来的包名继续。

> 实机核验｜【待 openEuler 24.03 LTS SP4 实机验证】本书需在目标仓库核对 vim-enhanced、man 文档包、开发工具和 JDK 候选包。包名示例不表示已经在本次环境成功安装。

### 9.2.2 安装后的证据

```bash
type vim
rpm -q vim-enhanced
rpm -ql vim-enhanced
```

rpm -q 中 q 是 query，查询一个已安装包；-ql 继续列出包里的文件。要查询 /usr/bin/vim 由谁提供，可用 rpm -qf /usr/bin/vim，f 对应 file。这能把终端中用到的程序关联回安装记录。

## 9.3 更新、移除与来源

### 9.3.1 变更前保留可恢复状态

dnf check-update 查询更新，退出状态 100 通常表示存在可用更新，不应被自动脚本一律当成故障。真正升级会改变系统，需要先保存工作与快照，检查交易内容。服务器应安排维护窗口，再确定是否需要重启进程或系统。安装历史便于追溯，不能保证任何更新都能完整回退，旧包可能已不可获取，数据格式也可能已经变化。

移除软件用 dnf remove 后接准确包名，先读依赖移除列表。不要练习移除 Bash、包管理器、SSH 或系统核心组件。对自己安装的可选工具，理解影响后再操作即可。

### 9.3.2 不混用不匹配的软件源

仓库配置常见于 /etc/yum.repos.d/ 中的 .repo 文件，但应通过本机配置确认。修改前先读取和备份。不要把 Ubuntu 的 apt 命令或旧 CentOS 源地址当作 openEuler 24.03 SP4 的安装方法。把别的发行版 RPM 强行装进来，也可能造成库依赖冲突。

从本地 RPM 安装时，DNF 仍可处理依赖。发布方签名、可信下载路径与包来源都要核对。遇到签名问题应调查原因，不能为了让命令通过就写入 gpgcheck=0。

## 9.4 本章练习

- 不要往前翻｜仓库索引、RPM 包和可执行文件有什么联系？
- 命令填空｜查询一个文件属于哪个已安装包使用 rpm ______ /路径。
- 看需求写命令｜搜索 Vim，并查询哪个包提供以 /vim 结尾的程序路径。
- 看命令猜结果｜dnf check-update 返回 100 是否一定表示网络失败？
- 找错误｜为修复安装错误而混入未知 CentOS 仓库，会引入哪些新变量？
- 无提示实操｜在虚拟机中为一个可选工具记录查询、交易摘要、安装后版本和文件归属。暂不做全系统升级。

本章新命令为 dnf / Dandified YUM、rpm / RPM Package Manager。把实际包名写进学习记录，三天后从一个程序路径反查包名。
