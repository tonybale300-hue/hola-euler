# 第 18 章 grep、find 与文本搜索

> 本章任务｜区分内容搜索与路径搜索，并保留含空格的文件名。

## 18.1 内容和名字是两种搜索

### 18.1.1 在日志里找一段文字

```bash
cd ~/linux-lab/text
grep -nF 'ERROR' app.log
grep -nF 'INFO' app.log
```

grep 的名称有历史来源，与 ed 编辑器的 g/re/p 操作有关，即按正则表达式选中行并打印。不要把它当成后来随意拼出的口号。[S17] -n 显示行号，-F 把模式当作固定字符串。本例找到包含 ERROR 的行，行号让你能够回到原文上下文。

grep 默认选择匹配行，无匹配时通常返回状态 1，出错时通常返回 2。没有输出可能是没匹配，也可能是输入有误而错误输出被重定向，判断时同时看错误与状态。

### 18.1.2 正则表达式从三个符号开始

正则表达式是描述文本模式的规则。^ 匹配行首，$ 匹配行尾，. 匹配一个字符。要匹配一行以 ERROR 开始，可写 grep '^ERROR' app.log。要查找字面 a.b，使用 grep -F 'a.b' 文件最直接；普通正则中的点需要转义才表示字面点。

```bash
grep -nE '^(WARN|ERROR)' app.log
```

-E 使用扩展正则，圆括号分组，| 表示候选之一。这里打印以 WARN 或 ERROR 开头的行。正则模式放进单引号，避免 Bash 先解释其中符号。Shell 的 *.log 文件名通配符与 grep 的正则表达式是不同语言，不要用同一套直觉混用。

## 18.2 按文件条件查找

### 18.2.1 find 沿目录树访问

```bash
find ~/linux-lab -type f -name '*.log' -print
```

find 就是查找。第一个参数是起点，-type f 只选普通文件，-name 按名称匹配，-print 输出路径。'*.log' 的引号让模式交给 find；去掉引号后，Shell 可能先根据当前目录展开，造成参数数量变化。

```text
find 起点 -type f -name '*.log' -print
     |     |        |           |
     |     |        |           +-- 显示结果
     |     |        +-------------- 名称条件
     |     +----------------------- 文件类型条件
     +----------------------------- 搜索范围
```

### 18.2.2 搜索范围本身就是保护

从 / 开始搜索会穿过大量系统目录，普通用户常遇到权限错误，还可能很慢。知道文件属于自己的实验时，从 ~/linux-lab 开始即可。find 也能执行删除和其他命令，但本章先只列出路径，先证明选中的对象正确，再决定后续动作。

## 18.3 把路径安全交给下一个命令

### 18.3.1 不按空格拆文件名

```bash
find ~/linux-lab -type f -name '*.log' \
  -exec grep -nH -F 'ERROR' {} +
```

-exec 指定对找到的路径执行命令，{} 表示这些路径的位置，末尾 + 允许合并多个路径为一批调用。grep 的 -H 强制显示文件名，方便多文件查询。本例避免把路径先按空格切开，因此含空格的文件名也能正确传入。

### 18.3.2 换行也可能属于文件名

Linux 文件名可以包含换行，虽然人通常不应该给工作文件取这样的名字。解析 ls 输出或写 for f in $(find ...) 会破坏这些名称。复杂流程可采用 NUL 分隔的 find -print0 与相应工具，或者像上面直接使用 -exec。初学者不必马上写复杂管道，但要知道普通文本行并非普遍安全的文件名边界。

## 18.4 本章练习

- 不要往前翻｜grep 搜什么，find 搜什么？
- 命令填空｜按字面搜索包含点的字符串可使用 grep ______ 'a.b' 文件。
- 看需求写命令｜列出实验目录内所有 .txt 普通文件。
- 看命令猜结果｜grep '^INFO' 会匹配前面有空格再出现 INFO 的行吗？
- 找错误｜find . -name *.txt 为什么会随当前目录内容改变行为？
- 无提示实操｜建立两份含空格文件名的日志，分别写入正常与错误行，用一个查询找出错误及文件名。
